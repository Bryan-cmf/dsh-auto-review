# PRD — dsh-auto-review（自動審查官）

> 版本 v1.0（定稿）· 2026-08-24 · 四項開放問題已拍板（見 §8 決定欄）

---

## 1. 背景與問題

目前項目產出（代碼、頁面、流程）的質量把關是**手工的**：要麼靠編碼代理自检（自己寫自己評，盲區明顯），要麼靠人事後抽查（不及時、不可持續）。已有兩個面板插件（運維、預覽）解決了「看見」的問題，但沒有解決「**把關—反饋—修復—複核**」這條閉環。

同時，本機 DSH 已配置 `zai/glm-5.3`（1M 上下文），具備把「審查」變成一個**獨立、強力、結構化**角色的全部條件——審查者與編碼者分離，是本產品的核心立意。

## 2. 產品定位

一個 DSH 插件：**用 GLM 5.3 對指定項目的產出做四維度審查，把優化建議自動輸入該項目的聊天框，驅動編碼代理完善代碼，循環複審直到完全通過驗收。**

```
        ┌────────────────────── dsh-auto-review ──────────────────────┐
        │                                                              │
 用戶 ──►│ /review 觸發 ──► 4×GLM5.3 審查代理(並行) ──► 聚合 findings   │
        │                     代碼│安全│流程│前端設計         │          │
        │                                                  ▼          │
        │              未通過 ◄──────── 建議清單注入聊天框(followup)     │
        │                 │              編碼代理修復 → whenIdle        │
        │                 └──► 複審(增量) ──► 全部通過 ──► 報告+停止 ✅  │
        └──────────────────────────────────────────────────────────────┘
```

## 3. 目標用戶與場景

**用戶**：在 DSH Web GUI 中開展編碼項目的所有者（你），以及未來開源後的 DSH 用戶。

**典型場景**：
- S1 會話收官：一輪開發完成，`/review` 發起全面體檢，建議回灌，修到綠燈。
- S2 持續把關：每次代理交付大功能後手動（或未來自動）觸發增量審查。
- S3 驗收交付：對指定路徑的任意項目（不必是當前會話的）做一次性審查報告。

## 4. 用戶故事

| # | 故事 | 驗收要點 |
|---|---|---|
| U1 | 作為用戶，我在項目會話輸入 `/review`，系統用 GLM 5.3 對項目做四維審查 | 命令直達；面板實時顯示四維度進度 |
| U2 | 作為用戶，我看到每個維度的發現清單（嚴重度/檔案/問題/建議） | 面板可展開；報告可導出 |
| U3 | 作為用戶，審查建議自動成為聊天框消息，編碼代理立即開始修復 | 注入消息帶審查官來源標識；代理確實接手 |
| U4 | 作為用戶，修復完成後系統自動複審，直到四維全綠或達到輪數上限 | 輪次計數可見；停止條件透明 |
| U5 | 作為用戶，我能隨時暫停/終止審查閉環 | `/review stop` + 面板按鈕 |
| U6 | 作為用戶，我能配置驗收口徑（嚴重度門檻、最大輪數、注入模式） | 設置項持久化（profile bundle 插件） |

## 5. 功能需求

### F1 審查維度（內建四個技能，提示詞隨插件發行）

| 維度 id | 名稱 | 審什麼 | 通過線（默認） |
|---|---|---|---|
| `code` | 代碼審查 | 正確性、可維護性、壞味道、錯誤處理、依賴健康 | 無 critical/high |
| `security` | 安全性審查 | 注入、越權、密鑰洩漏、不安全依賴、輸入校驗、路徑穿越 | 無 critical/high |
| `flow` | 用戶流程審查 | 任務流程完整性、邊界與異常分支、空/錯/載入態、可達性 | 無 critical/high |
| `design` | 前端設計風格及頁面審查 | 設計 token 一致性、排版層級、響應式、可訪問性、風格統一 | 無 critical/high |

每個維度 = 一個獨立 GLM 5.3 審查代理 + 該維度提示詞（checklist 化），**並行**執行。

### F2 審查範圍（定稿：每輪全量）
- **每一輪都對項目做全量複審**（複用 artifact-view 掃描邊界：深度≤4、排除 node_modules/.git 等、上限檔案數）——用戶明確選擇「最徹底」口徑，接受相應 token 成本；每輪同時複核上輪 findings 是否已修復。
- `/review <path>` 可審任意指定項目（S3 報告模式，不注入、只出報告）。

### F3 發現與報告
- Finding 結構：`{severity, file, line?, title, detail, suggestion}`，severity ∈ critical/high/medium/low。
- 每輪聚合報告（Markdown），面板可視 + `/__review/api/report` 可取。

### F4 聊天框注入（核心）
- 把「未通過維度」的 findings 組裝成一條結構清晰的用户消息，`followup` 注入目標會話。
- 消息帶明確來源標識（審查官第 N 輪），避免與人類輸入混淆。
- 注入前等待目標代理 idle（不打斷進行中的回合）。

### F5 閉環控制
- 停止條件（任一）：① 四維全部通過 ✅ ② 達最大輪數（默認 5，可配）③ 同一 finding 連續 3 輪未消除（振盪保護，轉人工）④ 用戶主動停止。
- 每個會話同時最多一個審查閉環在跑。

### F6 觸發與 UI
- 觸發：`/review [path]`、`/review stop`、`/review status` 命令；面板「開始審查」按鈕。
- 面板：conversation.view 新 tab（label「審查」，order 80），顯示輪次、四維狀態燈、findings 列表、注入歷史、控制按鈕。

### F7 配置（持久化，經 settings 服務）
| 配置 | 默認 | 說明 |
|---|---|---|
| `maxRounds` | 5 | 閉環輪數上限 |
| `severityGate` | critical+high | 通過線 |
| `injectMode` | **auto（定稿）** | 全自動注入；manual 為可切換開關 |
| `model` | zai / glm-5.3 | 可換審查模型（默認鎖 GLM 5.3） |
| `reviewerReadOnly` | true | 審查者工具集只讀 |

## 6. 非功能需求

- **N1 安全**：審查代理只讀（工具 restrict + 提示詞雙保險）；插件自身所有副作用可逆；絕不觸發服務重啟類操作。
- **N2 成本可見**：面板顯示每輪 token 消耗估計；增量審查控制成本。
- **N3 失敗隔離**：審查者崩潰 / zai 路由不可用 → 面板紅字 + 閉環安全終止，不影響宿主。
- **N4 個人工具就緒（定稿：不開源）**：`plugin-review.zsh` 掃描通過、零本機路徑硬編碼；README 中文即可（開源鐵律不觸發，若日後開源再補雙語）。
- **N5 併發**：四維並行；同會話單閉環；跨會話互不干擾。

## 7. 不做（Out of Scope，v1）

- ❌ 自動觸發（監聽會話完成事件後自動開審）—— 先手動，驗證價值後再議
- ❌ 審查者瀏覽器截圖式視覺審查 —— v1 為代碼級設計審查（可讀 HTML/CSS/JSX）
- ❌ 修改 PR / 多分支工作流
- ❌ 非 GLM 模型的自動擇優

## 8. 開放問題 → 定稿決定（2026-08-24 已全部拍板）

| # | 問題 | **定稿** |
|---|---|---|
| Q1 | 審查者形態 | ✅ **子代理會話**：provider `spawn`、outputSchema 結構化、toolFilter 只讀 |
| Q2 | 注入模式默認 | ✅ **全自動閉環**（auto）；最大輪數 5 + 振盪保護兜底，manual 可切 |
| Q3 | 審查範圍 | ✅ **每輪全量**（不走增量，接受 token 成本換徹底性） |
| Q4 | 發行形態 | ✅ **個人工具 + profile bundle**（不開源、不推 GitHub、不發 npm） |

## 9. 插件自身的驗收標準（M5 門檻）

1. 在真實項目會話 `/review` → 四維並行審查 → 面板實時可見 → 至少捕獲 3 類真實 findings。
2. 建議注入後，編碼代理確實執行修復；修復完成自動複審；全綠後閉環正常終止並出報告。
3. `/review stop`、面板停止按鈕、達輪數上限三條終止路徑全部演練通過。
4. 停用插件後：路由、命令、面板、監聽全部乾淨撤離（無殭屍路由）。
5. `plugin-review.zsh` 掃描 0 警告（個人工具，README 中文即可）。
6. profile bundle 部署後重啟一次即常駐（重啟已事先徵得同意）。
